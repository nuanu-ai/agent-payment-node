# Dependency audit — 2026-09-23

## Reproduction and scope

On `origin/main` at `59a6c1c` (APN `0.5.26`), Node `v26.7.0` and npm `11.19.0`:

```sh
npm ci --no-audit --no-fund
```

## Remediation work

1. Track upstream MetaMask/Fox SDK releases that remove or replace the vulnerable Solana and ethers v5 dependency chains. Fox SDK `2.8.0` still pins `@solana/spl-token@0.4.14`, so a direct Fox SDK bump alone does not remove the high finding.
2. Obtain a fixed `bigint-buffer` release or a compatible upstream removal of `@solana/buffer-layout-utils`/`bigint-buffer`. `@solana/spl-token@0.4.15` changes to buffer-layout-utils `^0.3.0`, but `0.3.0` still depends on `bigint-buffer@^1.1.5`; overriding Fox SDK's exact `0.4.14` pin would therefore add compatibility risk without clearing the advisory.
3. Ask `jayson`/`@solana/web3.js` upstream to migrate to `stream-json >=3.5.0`, or assess replacing that path. Do not override `stream-json` across a major-version gap without compatibility tests of Jayson request parsing and APN's affected flows.
4. For `elliptic`, track upstream migration away from ethers v5 and legacy crypto chains; do not force a major replacement below MetaMask SDK.
5. Repeat both audit modes after each upstream change. Require a clean `npm ci`, build, typecheck, relevant tests, and identical package lock and shrinkwrap before treating the advisory as resolved. Separately inspect runtime call paths and attacker-controlled input boundaries for the three vulnerable functions.

The existing five-high sprint figure is still current. This document closes the measurement task and leaves dependency remediation open.

## 24 Sep high-advisory call-path review

On current `origin/main` `246aa847`, the locked production chain is still `@metamask/fox-sdk@2.7.0` → `@solana/spl-token@0.4.14` → `@solana/buffer-layout-utils@0.2.0` → `bigint-buffer@1.1.5` (`npm ls --all --omit=dev`). The [reviewed advisory](https://github.com/advisories/GHSA-3gc7-fjrx-p6mg) lists every published `bigint-buffer` version through `1.1.5` as affected, with no patched version, and describes an application crash via `toBigIntLE()`. The npm registry still reports `1.1.5` as latest on 24 Sep.

The installed `@solana/buffer-layout-utils/lib/cjs/bigint.js` calls `toBigIntLE(Buffer.from(src))` when a little-endian bigint layout is **decoded**, and `toBigIntBE` for the big-endian layout. Its exported `u64` layout has a fixed eight-byte span. SPL Token uses that `u64` layout to decode fields such as token-account `amount` and mint `supply`; those state decoders accept account bytes from Solana RPC. Thus a Solana token-account decode is a plausible route to the affected function in a consumer that enables the Fox Solana wallet. The fixed layout span also bounds the byte length passed by these specific decoders; this review did not establish an exploit through them.

APN's supported MetaMask gasless helper uses `@metamask/agent-sdk/base`, `@metamask/agent-sdk`, `@metamask/agent-sdk/evm`, `@metamask/fox-sdk/wallets/evm`, and `@metamask/fox-sdk/wallets/keyring` in `service.ts` and `session.ts`. It has no Solana SDK import or SPL Token decode call. In the installed Fox SDK distribution, the only JavaScript file referencing `@solana/spl-token` is `dist/wallets/solana/index.js`. An offline Node import probe of all five APN entry points found no `bigint-buffer`, `@solana/buffer-layout-utils`, or `@solana/spl-token` entry in `require.cache`. This is evidence against an import-time call path in the tested package versions, not proof that every runtime branch in the SDK avoids the converter. No untrusted Solana account bytes were sent to these entry points in this review.

No compatible patched `bigint-buffer` release or upstream replacement is available for the locked chain. Fox SDK's own `lavamoat.allowScripts` denies the nested `bigint-buffer` install script, but APN's ordinary npm install does not inherit that policy; the native addon was present after installation in the reviewed worktree. Disabling install scripts globally or forcing an unrelated package override would affect other dependencies without establishing a supported fix. Keep C1-11 open with **five high affected records** until a patched/removing upstream version is locked and audited, or a separately reviewed runtime boundary proves the affected decoder unreachable for all supported APN operations.

APN's MetaMask gasless helper imports Fox EVM and keyring entry points rather than its Solana entry point, but that source boundary alone does not prove the high advisory unreachable in every transitive SDK path.

## 24 Sep gasless helper runtime boundary candidate

The supported gasless helper runs in a dedicated Node subprocess. Its bootstrap now registers a synchronous module resolution hook before importing the helper service. The hook rejects the Fox Solana wallet entry point, `@solana/spl-token`, `@solana/buffer-layout-utils`, and `bigint-buffer` by package specifier and resolved package path. A future EVM SDK branch that tries to load those modules fails closed in the helper rather than reaching the vulnerable converter. The parent maps a helper failure to its existing provider failure or unknown-submission result; the guard does not alter payment state or retry behavior.

On the locked Fox SDK `2.7.0` distribution, only `dist/wallets/solana/index.js` and `index.mjs` reference `@solana/spl-token`; the EVM and keyring exports do not. Offline tests run all five supported helper modes (`inspect`, `quote`, `buildUnsigned`, `submit`, `observe`) with the hook installed and synthetic network responses. Separate tests verify that both ESM and CommonJS attempts to load the affected packages are rejected and that a rejected load yields a closed helper failure. The existing parent subprocess test exercises the new bootstrap entry. These tests cover the APN gasless helper boundary and the locked dependency graph; they do not establish that other APN features cannot load `bigint-buffer` or remove the package from the production installation.

At this helper-only stage, the npm advisory remained **five high affected records** and C1-11 remained open pending an upstream fixed/removing dependency release or broader APN runtime coverage. A package lock refresh or SDK upgrade must repeat the boundary and helper behavior tests.

## 24 Sep shipped runtime coverage

On fresh `origin/main` `76c7453` (including PR #263), a clean `npm ci --no-audit --no-fund` installed the locked dependencies. Both `npm audit --omit=dev --json` and full `npm audit --json` still report **53 affected records: 5 high, 0 moderate, 48 low, 0 critical**. The five high records are `@metamask/agent-sdk`, `@metamask/fox-sdk`, `@solana/spl-token`, `@solana/buffer-layout-utils`, and `bigint-buffer`; the vulnerable `bigint-buffer@1.1.5` remains installed. The package lock and shrinkwrap were not changed.

The package declares one executable, `bin/apn.js`. Its `dist/bin.js` dispatches CLI commands and stdio MCP. `npm pack --ignore-scripts --dry-run --json` confirmed that the executable, `dist/bin.js`, the shared dependency guard, and the helper bootstrap are all included. `package.json` names `index.js` as `main`, but that file is absent from the package; APN exposes no supported library API through that field. The other `dist` modules are shipped as implementation files, not documented standalone entrypoints. The additional shipped Node process is `dist/metamask-gasless/client/helper-bootstrap.js`, launched by `metamask-gasless/client/process.ts` for MetaMask gasless operations.

Source inventory found only literal dynamic imports: `bin/apn.js` loads `dist/bin.js`; the helper bootstrap loads `helper-entry.js`; the helper service/session load `@metamask/agent-sdk` base/EVM, Fox EVM/keyring, and `@toruslabs/ethereum-controllers`. Other `import(...)` occurrences in `src` are TypeScript type references. Runtime `createRequire` calls in the MetaMask, Smart Account, and Awal package checks resolve manifests only. APN's separate local Solana implementation uses `@solana/kit` and `@solana-program/*`, not Fox's Solana wallet.

The executable now installs the same synchronous Node module resolution guard **before** dynamically loading `dist/bin.js`; the helper keeps its guard before loading service code. The guard rejects Fox's Solana wallet, SPL Token, buffer layout utils, and `bigint-buffer` by bare specifier and resolved package path for both ESM and CommonJS. It remains active for later SDK imports in the process, so a future CLI/MCP branch attempting that decoder fails closed. An offline subprocess test starts the actual shipped executable in CLI discovery and MCP config modes, then attempts all forbidden imports through ESM and CommonJS, including a direct resolved package file path; all are rejected. It also imports `@solana/kit` successfully. Existing helper tests verify the five supported gasless modes and forbidden imports. Typecheck/build passed, and the focused MetaMask gasless, Smart Account gasless, and local Solana compatibility suite passed 30/30 tests. No blockchain RPC, credentials, or payment was used.

This closes the sprint's **runtime reachability mitigation** for supported APN CLI and stdio MCP operations on the tested Node 26.7.0 / locked package graph. It does not fix or uninstall `bigint-buffer`, prove behavior for direct unsupported imports of internal `dist` files, or establish a clean vulnerability audit. Recheck this boundary, package inventory, and compatibility after dependency, entrypoint, or Node runtime changes; keep upstream replacement of the five high records tracked separately.
