# Gasless USDT staged implementation

This package contains Ethereum USDT gasless capability checks and a guarded send core. It contains the exact asset, chain and sponsor registry; quote, paymaster, UserOperation and receipt codecs; nonce, balance and allowance-slot reads; stable refusal classification; and a read-only rehearsal fixture. The `gasless usdt prepare` CLI and MCP commands save an unsigned, policy-bound operation. `gasless usdt status` reads that saved binding. Foreground CLI execution is separate from MCP.

`LocalUsdtSigningService` signs the saved binding in local custody. `UsdtExecutionJournal` reserves common asset usage and persists the may-have-sent marker. `GuardedUsdtSendService` issues at most one `eth_sendUserOperation` call through the fixed keyless Pimlico endpoint after fresh guards and a durable hash-bound marker. A separate effect lock protects signing and the submit marker against concurrent cleanup. A failed or interrupted pre-submit attempt is marked `failed_before_effect` and releases its usage reservation; only an operation with no submitting marker can take this path. `UsdtRecoveryService` makes one observation pass for an existing hash-bound submission. `usdtPacedRecoveryPort` supplies persisted provider pacing and deadline; one pass uses at most one keyless Pimlico read and four public Ethereum reads, without retry. Recovery requires the bundler's exact UserOperation identity, Ethereum chain 1, a transaction receipt in a canonical finalized block, and the EntryPoint event. Successful settlement also requires the exact USDT recipient and treasury transfers; a confirmed failed UserOperation event releases the usage reservation. Missing or conflicting evidence remains `unknown_finality` and never triggers another send. The foreground CLI wires execution and observation; MCP exposes unsigned prepare and read-only status only. The rehearsal loads no key, signs nothing and sends nothing.

Every request is bound to Ethereum chain 1, the pinned USDT contract, EntryPoint, delegate, paymaster and treasury, exact sender/recipient, gross amount, fee cap, minimum received amount, quote storage layout, gas price and paymaster validity. Any identity, chain, amount, expiry, prototype or excess mismatch fails closed with a stable `capability unavailable` or typed refusal reason. Provider text is bounded and never returned as a secret.

## Read-only rehearsal

After building the package, run the fixture with an explicit RPC URL:

```sh
APN_ETHEREUM_RPC_URL=https://example.invalid node scripts/gasless-usdt-rehearsal.mjs \
  --sender 0x823A3a5BaB1186141b32fC65F8E25Ca24c679Ce7 \
  --to 0x000000000000000000000000000000000000dEaD \
  --amount 1 --max-fee 0.5 --min-received 0.5
```

This stops before any signature and does not read APN state.

## Policy bound local prepare core

New CLI/MCP preparations use bound-operation v2. Its initial quote and fast price are informational facts; the gas fields, initial prices, gross, fee cap, net amount and calldata remain frozen. The sponsor payload's authenticated exchange rate and postOp overhead determine the reported signed fee bound, which must fit the same fee cap. A later valid quote or fast-price change is recorded with an exact changed-field list and does not reprice the frozen operation. Signed bytes are never rewritten. The initial estimated fee may exceed the cap; authenticated signed economics must still fit. V2 verifies the pinned deployed paymaster's inherited historical V7 hash, EIP-191 signer recovery, signer membership and getHash parity in one canonical-block RPC batch before publication.

Persisted v1 records retain their original strict quote/rate/drift validators and exact bytes. V1 and v2 share the original v1-derived claim filename namespace: the first claim wins without migration or authentication backfill. The legacy `preparePolicyBoundUsdt` API below remains available for that version.

`preparePolicyBoundUsdt` is a domain-only, unsigned preparation API. Its adapter must supply the authenticated active owner policy, combined daily USDT usage, a trusted clock, and account state at one canonical Ethereum safe block. The sponsor is the fixed keyless Pimlico endpoint. The API refuses a missing, revoked, expired, mismatched or unadmitted policy; the owner account, Ethereum USDT identity, gasless mechanism pin and positive per-transfer and daily caps must match exactly. It requires the signed paymaster rate to equal the quote rate and checks both against the fee budget, repeats the quote and policy reads after sponsor data, and returns an immutable copy of the prepared data with a binding hash covering the policy revision, safe block, account nonce, fee plan, paymaster data and unsigned operation.

The frozen account batch calls USDT `approve(paymaster, 0)`, then `approve(paymaster, F)`, then `transfer(recipient, N)`, in that order. The paymaster request sees this exact calldata. Preparation remains unsigned.

The separate `UsdtBoundOperationRepository` and `GaslessUsdtOperationService.prepareBound` persist the complete preparation as a private, integrity-checked local record. The state root's parent must exist; creating or reopening each private directory syncs its parent, and an unsupported directory fsync refuses preparation. A complete, fsynced file is published through an exclusive link for each idempotency key before the final operation file; competing processes cannot claim the same key for different bindings. This claim is shared across profiles **within the bound Gasless USDT journal only**. The same key can create a separate operation in another payment family, including the older dormant USDT journal. A matching retry checks the durable claim and frozen caller intent before reading current policy or public RPC, then returns the first saved bound record even if time, policy, safe block or sponsor data has changed. A different recipient, amount or profile under the same key is refused before those reads. If publication stops after the claim, `statusBound` reads that complete claim and a matching retry restores the final file. Stale incomplete temporary files are cleaned up. `resumeBound` rechecks the active owner policy, usage admission, paymaster expiry and safe chain snapshot, returning a read-only classification. Revocation, policy changes and nonce drift fail closed for recovery. A later safe block without proof of the original block's canonicality requires recovery. The older dormant v1 journal remains readable for existing status callers and does not contain the complete binding. The separate execution journal rechecks policy and account state, reserves shared usage, and persists the signed UserOperation hash before dispatch. An ambiguous response or mismatched acknowledgement stays `unknown_finality`; subsequent calls never rebroadcast. There is no fresh mainnet transfer acceptance.

## Foreground execution and observation

`apn gasless usdt execute --profile-hash <hash> --operation <operation-id>` loads only an existing bound operation. The terminal presents Ethereum, owner, recipient, gross amount, exact recipient amount, the requested maximum fee and the effective fee cap `F = min(maxFee, gross - minReceived)`, the quoted fee bound, bound policy revision and digest, and saved paymaster quote validity. It names the Pimlico sponsor, pinned paymaster (USDT spender), and signed fee treasury. The batch grants the paymaster exactly `F` USDT allowance; after a successful fee charge `A`, `F - A` may remain approved until a later gasless USDT batch resets it. On first use, the prompt identifies the EIP-7702 delegate and warns that its on-chain designation can persist after the transfer. The operator must type the displayed code. The command then rechecks the active policy, saved quote expiry and fee cap, and safe account state; it does not request a new sponsor quote. It reserves shared usage. For v2, one fresh sponsor-authentication batch reuses the second reserve guard's verified snapshot, followed by a fresh owner-policy/usage/time fence before custody. A nonserializable single-use permit binds the exact operation and wallet identity; it expires after 5 seconds and is consumed under the custody lock before key access. Missing, reused or delayed permits refuse without an automatic extra read. Current payload validity and the 5-second authentication age are checked again after awaited secret retrieval, immediately before each wallet signature. Sponsor membership is point-in-time evidence, not an inclusion guarantee. The shared execution read budget remains seven admissions: four snapshot batches before custody, one authentication batch, and two final snapshot batches. The command then signs locally, independently verifies the signed UserOperation, persists its hash and `submitting` state, and issues one `eth_sendUserOperation` to the fixed keyless Pimlico endpoint. If signing or a fresh guard fails before `submitting`, the command records `failed_before_effect` and releases the reserved quota. On restart, `execute` repairs any leftover `planned` or `reserved` journal under the effect lock, refuses that old operation, and requires a new preparation. A lost or mismatched send response is `unknown_finality`; another execute call never resends. `apn gasless usdt execution-status` reads the local journal. `apn gasless usdt observe` uses the original saved hash and a finalized canonical receipt to update the journal; it never signs or sends. These three commands have no MCP tool. `APN_ETHEREUM_RPC_URL` is required for live checks and observation. No fresh mainnet transfer acceptance has been recorded.

## Unsigned command and read budget

`apn gasless usdt prepare --profile <profile> --to <recipient> --amount <gross-USDT> --max-fee <USDT> --min-received <USDT> --idempotency-key <key>` reads the authenticated active owner policy and combined daily USDT usage before public RPC. It binds the owner's Ethereum account, active policy digest/revision/activation, exact USDT and paymaster mechanism, positive transfer and daily caps, and one canonical safe-block account snapshot. It saves the complete unsigned operation. The idempotency key protects this bound journal across all profiles and does not reserve the key in other payment families. The matching MCP tool is `apn_gasless_usdt_prepare`. Read it with `apn gasless usdt status --profile-hash <hash> --operation <operation-id>` or `apn_gasless_usdt_status`.

New v2 preparation permits at most **8 read admissions**, with no retry, polling or fallback to single reads. Ethereum uses two strict JSON-RPC batches: chain ID plus safe block identity, then four pinned code hashes, four contract invariants, owner code, USDT balance, EntryPoint nonce and EOA nonce bound to that canonical safe block hash. A malformed, missing, duplicate or mismatched batch response refuses preparation. The EOA nonce is needed for the unsigned EIP-7702 authorization stub when the account is undelegated. The fixed sponsor still uses five separate calls: quote twice, gas price twice and paymaster data once. For v2, the second quote and gas-price reads record informational changes; malformed or wrong-route quotes still refuse. A third Ethereum batch authenticates sponsor membership and exact getHash parity at the saved canonical safe-block hash. An admission can be counted before scheduling rejects it, so this limit is not a measured physical-dispatch counter. Legacy v1 retains its exact drift check. The command has a 60-second total read deadline; each endpoint family shares one persisted in-flight slot and a fail-closed 429 cooldown. Public Pimlico starts are at least 3 seconds apart to respect its 20 requests/minute limit; other public RPC starts are at least 750 ms apart. New membership/getHash EIP-1898 endpoint behavior and live payment acceptance remain unverified; unsupported canonical-hash calls refuse without latest/number fallback.

V2 CLI/MCP results redact raw sponsor payload/signature and authorization bytes. Their saved sponsor capture is explicitly labelled as point-in-time evidence, not current authorization.

## Installed package no-money acceptance

After `npm run build`, run `node --test tests/packaging/gasless-usdt-installed.test.mjs`. The test packs APN, installs that archive in a temporary sandbox, and imports only the installed package. Deterministic local policy, safe-block and sponsor ports prepare one synthetic 1 USDT operation, verify its durable unsigned journal, status and exact replay, and refuse an amount above the owner cap before public reads. An injected approval refusal proves the installed CLI stops before the signer, wallet secret, usage reservation or dispatch. The installed execution journal then binds a second synthetic operation to one shared USDT usage lease, persists and replays the reserved record, durably releases the lease through pre-effect cleanup, and records a synthetic hash-bound `submitting` marker. The installed CLI observes a deliberately mismatched bundler identity, records `unknown_finality`, and retains the usage lease; the test reopens the journal, checks integrity, and confirms no dispatch occurred. The installed read-budget transport also permits seven read admissions and refuses an eighth; its fake transport records the corresponding seven dispatches. This proves the local installed-package path with synthetic inputs; it does not exercise public RPC compatibility, signing, broadcast or mainnet payment acceptance.
