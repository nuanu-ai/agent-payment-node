# Base native Relay routes

`relay native prepare`, `relay native execute`, `relay status`, `relay observe` and `relay retire` support two Base ETH source routes for any profile. Existing BNB routes and saved receipt identities remain valid.

| Mechanism reference | Source | Destination | `--destination-chain` |
| --- | --- | --- | --- |
| `base-native-megaeth-usdm-v1` | Base ETH | MegaETH USDm `0xFAfDdbb3FC7688494971a79cc65DCa3EF82079E7` | `eip155:4326` |
| `base-native-polygon-native-v1` | Base ETH | Polygon POL | `eip155:137` |

The payer is the wallet of `--profile`. The recipient, principal (`--amount-atomic`), minimum output (`--min-output-atomic`) and full fee budget (`--max-deposit-network-fee-wei`) are the caller's required inputs and appear on the foreground confirmation. The profile's active Base native bridge policy must admit the exact mechanism reference with its account equal to the profile wallet; its per-transfer and daily caps bound the principal. Use `mechanismOptions.bridge` to admit both references with individual caps and one daily cap, and an optional `recipients` pin to restrict who may receive. No policy is installed automatically.

```sh
apn relay native prepare --profile <profile> --source-chain eip155:8453 --destination-chain eip155:4326 --recipient <address> --amount-atomic 60000000000000 --min-output-atomic 100000000000000000 --max-deposit-network-fee-wei 1500000000000 --idempotency-key relay-base-mega-0001
apn relay native execute --profile <profile> --operation <saved-operation-id> --rpc-url https://mainnet.base.org
apn relay observe --profile <profile> --operation <saved-operation-id> --rpc-url https://mainnet.base.org --bnb-rpc-url https://mainnet.megaeth.com/rpc
```

For POL, use `--destination-chain eip155:137` and a POL minimum. `--bnb-rpc-url` is the retained destination RPC option name; the observer verifies the saved destination chain. These routes use the same CLI-only `relay native prepare` and `relay native execute` contracts as the BNB native routes; no Relay command is exposed as an MCP tool. Execution requires foreground terminal confirmation.

Operations prepared by earlier releases under `base-native-mega-usdm-default-v1` or `base-native-polygon-native-buyer-v1` keep loading, executing, observing and retiring under the policy pin they were prepared with. A new prepare never names those references; restage the policy with the references above.

The quote validator recomputes the official vendored Relay settlement SDK order ID, recovers the pinned solver, and re-encodes the exact native deposit. It rejects extra steps/output calls, changed currencies/recipients, malformed status locators, lower outputs and changed refund rows. The source refund row pays the payer; the destination refund row pays the recipient (Polygon refunds in USDC, final output remains native POL).

Source execution simulates the exact deposit against fresh canonical balance and nonce. Its full fee check adds the GasPriceOracle L1 fee upper bound for at most 512 signed bytes and the operator fee to the L2 gas budget and refuses before signing when the total exceeds the consented `--max-deposit-network-fee-wei`; the receipt fee is checked against the same ceiling. OP Stack total fees have no transaction-level cap; the ceiling is a verified pre-submission bound. New preparations bind the exact allowlist activation. Historical Base quotes without that field remain readable and retireable when untouched, but require fresh preparation before execution. Execution holds both wallet-profile and allowlist-profile lock identities plus the EVM owner lock through the first sign and physical POST. The provider's immutable signed deadline is the settlement/refund window; it may outlive the policy. Preparation requires a positive source authorization window bounded by that deadline minus the 60-second margin and the captured policy expiry, and rechecks the same active revision/digest/activation after quoting. Foreground authority expires at the earlier of the policy window and quote deadline minus the execution margin; it is checked after wallet loading, provider pacing, DNS and TLS immediately before the request body is sent. Independent create-only, fsynced signing and broadcast claims bind the operation, Base chain, owner, original nonce/wire hash and envelope, so restoring an older mutable journal cannot authorize another send. An ambiguous send is observed using the saved hash and never repeated.

Base source finality requires a stable canonical safe checkpoint. Provider status is only an assertion and destination hash hint. Every destination proof credits only the operation's own recipient. Mega USDm credit requires a successful canonical safe receipt with exactly one pinned-token Transfer to the recipient. Polygon credit, from any source chain, requires the milestone-finalized checkpoint and either a direct native transfer to the recipient or exactly one Relay router v3 native transfer event naming the recipient. Each destination proof uses at most two RPC POSTs. Operational acceptance additionally requires provider success and a source hash match, and one payout can accept one operation only. Neither result asserts cryptographic Relay order causality or an external merchant purchase.

Refund destinations remain signed-order-bound. Provider refund/failure status cannot release a confirmed source principal reservation or authorize another send. Untouched attempts can be retired through the existing local lifecycle. A Base attempt with a durable signing marker and missing signed material retains unknown usage and owner holds; it cannot be signed again or retired as no-effect. Native gas acquisition and merchant payment are separate commands outside these routes.
