# Fixed historical Jupiter retirement reads

This module adds a strict public record codec, a current-policy calculation and a common-ledger read projection for the three fixed historical Jupiter operation IDs. It adds no writer, financial authority, key access, RPC, signing, sending or CLI command. A sealed DTO is testable evidence, not permission to commit economic retirement.

The original native reservation stays byte-for-byte unchanged: amount 1,000,000 lamports, original reservedAt, null effectAt and unknown outcome. An immutable record in `jupiter-historical-retirements/<operationId>.json` will replace that unresolved hold's daily contribution with the authenticated total cap of 6,000,000 on its accountingAt UTC day. Its contribution is zero on later days and the old hold stays suppressed. This allocation does not establish historical submission, finality or actual fees.

`calculateHistoricalRetirementPolicy` requires current owner/profile/account/chain/asset admission with the same original finite SOL-to-USDC route. It tests the full 6,000,000 against the current per-operation limit, then tests the additional 5,000,000 against usage U including the original 1,000,000 hold. Three independent records therefore allocate 18,000,000 total with a 15,000,000 additional admission. Neither the code cap nor a saved policy snapshot grants owner permission.

`HistoricalRetirementRecord` binds the unchanged original operation and reservation, original reservation raw SHA256, current root UID/device/inode snapshot, native bucket, original/fresh cap, authenticated material metadata, retained claim evidence, affirmative canonical future-invalidity witness and current policy calculation. Strict validation rejects invented fee/finality fields, missing or reported-status canonical evidence, duplicate RPC origins, conflicting caps, invalid deadlines and an authority deadline extending beyond policy TTL. The canonical witness is structural public evidence from PART A; it cannot mint authority.

`JupiterHistoricalRetirementReader.forBucket` reads only existing owned records with normal no-follow secure-state primitives. It verifies the actual original operation, actual original reservation bytes and current root identity. It provides no commit method. All five common-ledger sum calculations use the same narrow projection, including nonpersistent usageReadOnly and normal reserve admission. Corrupt evidence refuses instead of releasing capacity.

The next private composition must consume genuine production one-use authority, explicit retirement-purpose terminal consent, canonical configured RPC proof and fresh current policy under held owner/operation scope through the native bucket commit. Its atomic one-create record is the accounting commit point. Separate additive terminal journal and `retired_unknown` receipt can then recover from that record without a second charge. They must preserve the original swap namespace and unknown history.

Before any ordinary ledger transition writes a bound retired row, that composition must add a narrow held-bucket immutability guard. The reader's rejection after a changed row is fail-closed accounting, but does not by itself prevent that mutation. This source packet does not claim that guard or production retirement authority exists.

Helper fixtures prove codec, arithmetic, read projection and refusal behavior only. Actual fixed-owner positive retirement remains unproven. Existing historical-authenticate, normal swap lifecycle, SDK, MCP catalog and vendor source remain unchanged.
